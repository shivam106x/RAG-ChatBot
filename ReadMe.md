# 📚 RAG Document Chat

> **Multi-document Retrieval-Augmented Generation** — upload your PDFs, DOCX, and TXT files, then ask questions and get answers grounded strictly in your documents.

---

## ✨ Features

- **Multi-document upload** — index any number of PDF, DOCX, or TXT files in one go
- **FAISS vector search** — fast, local similarity search powered by Facebook AI Similarity Search
- **Local embeddings** — uses `all-MiniLM-L6-v2` via `sentence-transformers` (no external embedding API calls)
- **Groq LLM generation** — answers generated by Groq's API, grounded strictly in retrieved context
- **Smart comparison retrieval** — auto-detects comparison questions ("compare", "both", "vs", …) and retrieves representative chunks from *every* source document to prevent single-document bias
- **Source citations** — every answer is accompanied by the document name and page number it came from
- **Reset knowledge base** — wipe all indexed documents with a single click
- **Streamlit UI** — clean, browser-based chat interface
- **FastAPI backend** — REST API that can be used independently of the UI
- **Docker-ready** — run the entire backend in a container

## 🏗️ Architecture

```
┌─────────────────────┐        HTTP        ┌──────────────────────────┐
│   Streamlit UI      │ ─────────────────► │   FastAPI Backend        │
│  (streamlitapp.py)  │ ◄───────────────── │   (backend/main.py)      │
└─────────────────────┘    JSON responses  └───────────┬──────────────┘
                                                       │
                                               rag_pipeline.py
                                                       │
                           ┌───────────────────────────┼──────────────────────────┐
                           │                           │                          │
                    Document Loading            FAISS Index              Groq API (LLM)
                  (PDF / DOCX / TXT)        (local, in-memory)       (answer generation)
                           │
                  SentenceTransformer
                  (all-MiniLM-L6-v2)
                   local embeddings
```

**RAG flow for every query:**

1. User question → embed with `all-MiniLM-L6-v2`
2. Retrieve top-k chunks from FAISS (or per-document chunks for comparison questions)
3. Build a prompt with the retrieved context and strict grounding rules
4. Send to Groq API → return answer + source citations

## 🚀 Getting Started

### Prerequisites

| Requirement | Version |
|-------------|---------|
| Python      | ≥ 3.10  |
| pip         | latest  |
| Groq API key | [console.groq.com](https://console.groq.com) |

### 1. Clone the repository

```bash
git clone https://github.com/your-username/RAG-ChatBot.git
cd RAG-ChatBot
```

### 2. Create and activate a virtual environment

```bash
python -m venv venv

# Windows
venv\Scripts\activate

# macOS / Linux
source venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure environment variables

Create a `.env` file in the project root:

```env
GROQ_API_KEY=your_groq_api_key_here
```

> ⚠️ **Never commit your `.env` file.** It is already listed in `.gitignore`.

### 5. Start the FastAPI backend

```bash
uvicorn backend.main:app --host 127.0.0.1 --port 8001 --reload
```

The API will be available at `http://127.0.0.1:8001`.  
Interactive docs: `http://127.0.0.1:8001/docs`

### 6. Start the Streamlit UI

Open a **second terminal** (with the virtual environment activated):

```bash
streamlit run streamlitapp.py
```

The app will open automatically at `http://localhost:8501`.

## 🐳 Docker

Build and run the FastAPI backend in Docker:

```bash
# Build
docker build -t rag-chatbot .

# Run
docker run -p 8001:8000 --env-file .env rag-chatbot
```

The backend listens on `$PORT` (defaults to `8000` inside the container, mapped to `8001` on your host).

## 🔌 API Reference

| Method | Endpoint  | Description                              |
|--------|-----------|------------------------------------------|
| GET    | `/`       | Health check                             |
| GET    | `/status` | Knowledge base status (docs & chunks)   |
| POST   | `/upload` | Upload and index one or more documents   |
| POST   | `/query`  | Ask a question against indexed documents |
| POST   | `/reset`  | Clear the in-memory knowledge base       |

### `POST /upload`

Upload files as `multipart/form-data` (field name: `files`).

**Response:**
```json
{
  "message": "Documents indexed successfully.",
  "documents_uploaded": ["report.pdf", "notes.txt"],
  "chunks_created": 42,
  "total_documents": 2,
  "total_chunks": 42
}
```

### `POST /query`

```json
{
  "question": "What are the main conclusions?",
  "compare": false
}
```

Set `"compare": true` to force document-aware comparison retrieval.

**Response:**
```json
{
  "question": "What are the main conclusions?",
  "answer": "According to the documents...",
  "sources": [
    { "source": "uploads/report.pdf", "page": 2 }
  ],
  "retrieved_chunks": 5
}
```

## ⚙️ Configuration

All tuneable parameters live at the top of `rag_pipeline.py`:

| Parameter | Default | Description |
|-----------|---------|-------------|
| `EMBEDDING_MODEL_NAME` | `all-MiniLM-L6-v2` | Local sentence-transformer model |
| `GROQ_MODEL_NAME` | `openai/gpt-oss-20b` | Groq model for answer generation |
| `CHUNK_SIZE` | `500` | Characters per chunk |
| `CHUNK_OVERLAP` | `100` | Overlap between consecutive chunks |
| `TOP_K` | `5` | Retrieved chunks for normal queries |
| `COMPARISON_CHUNKS_PER_DOCUMENT` | `6` | Chunks per document for comparison queries |

## 🛡️ How Grounding Works

The LLM is instructed to:

1. Use **only** the retrieved document context — no outside knowledge
2. Never invent facts
3. Explicitly cite source documents for comparison answers
4. Respond with *"I don't know based on the provided documents."* when the context is insufficient
